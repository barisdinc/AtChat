ATCHAT Protocol Specification

A robust digital mode for amateur radio: SSTV-simple to operate, but able to carry image/file transfer with error correction (ARQ) plus a multi-station text net (NET) inside a single 2.7 kHz SSB channel. Inspired by KG-STV, EasyPal and HSModem.

Status. Software design + simulation. The modem is a real OFDM modulator/demodulator producing and decoding real audio, with real bit errors under real simulated noise. The “channel” is a TCP server carrying those samples; it is not yet wired to a sound card or an SDR. Version described: 0.1.1.

1  Layering model

Three layers, deliberately separated. Moving to a real radio is expected to replace only the channel-access layer (TCP transport → sound card / SDR); the PHY and the NET protocol are unchanged. Two implementations track each other bit-for-bit: the reference Python (*.py at the repo root) and a Rust port (rust/), cross-checked with vectors.

2.2  On-air waveform structure

2.3  Frequency-domain differential coding

Both the header and the data symbols carry information as the phase difference between adjacent subcarriers, not as an absolute phase. A small sync error produces a phase ramp that is roughly linear in the carrier index k; that ramp cancels between neighbours, leaving only a small constant residue. This buys noise robustness without any channel estimation or equaliser (classic differential OFDM).

Bit-stream order is MSB-first over the payload bytes. For QPSK, carrier k carries bits [2k, 2k+1]. Decoding per differential value d: QPSK bit0 = real(d)<0, bit1 = imag(d)<0; BPSK bit = real(d)<0. Concatenate all symbols’ bits, truncate to payload_len·8, pack to bytes → full.

2.6  Payload framing & CRC

full = payload  ‖  CRC32(payload) as 4 bytes big-endian

RX splits payload = full[:payload_len−4] and rejects the frame (returns “nothing”) if crc32(payload) != crc_recv. There is no partial-frame recovery at the PHY — that is the ARQ layer’s job.

2.7  Synchronisation (Schmidl-Cox style)

2.8  Time on air

bits_needed     = payload_len * 8              # payload_len already includes the CRC
bits_per_symbol = 152 (QPSK) | 76 (BPSK)
data_symbols    = ceil(bits_needed / bits_per_symbol)
airtime         = (2 + data_symbols) * 320 / 8000  seconds   # = (2 + data_symbols) * 40 ms

Fixed cost per transmission: preamble + header = 80 ms. A 220-byte file block, wrapped in its BULK_BLOCK JSON (~420 bytes on the wire), is ≈ 1.0 s on air at QPSK.

3.2  Half-duplex arbitration

The channel keeps a single busy_until timestamp. There is no queue and no priority — pure listen-before-talk; all back-off intelligence is on the client. Delivery is deliberately delayed by duration so airtime is physically modelled.

3.3  Client-side LBT + exponential back-off

3.4  Impairments (optional, for realism)

Applied in order to the int16 samples before broadcast: (1) multipath echo x += gain · delay(x, d) where d = delay_ms/1000 · 8000 samples (meaningful up to the 8 ms guard); (2) AWGN with power mean(x²) / 10^(SNR_dB/10). CLI: --snr, --multipath-delay-ms, --multipath-gain.

4  NET protocol frames

The NET protocol lives inside the modulated payload: frame is a JSON object, json.dumps-ed, handed to modem.modulate, and recovered by modem.demodulate + json.loads on every receiver.

4.1  Common envelope

FieldTypeNotes
typestringone of the types below
srcstringsender callsign
dststring"ALL" for broadcast, or a callsign for directed. Default "ALL"

A receiver acts on a frame when dst ∈ {"ALL", own callsign}. A station ignores its own src.

4.2  Frame catalogue

JOIN_REQUEST

{type, src, dst:"ALL"}. Announces arrival — sent on first connect and on every /reconnect. If a receiver has a half-finished inbound transfer from src, seeing this frame makes it re-issue the BULK_STATUS for the missing blocks.

BEACON

FieldTypeMeaning
src / dstmaster callsign / "ALL"
backupstring | nullthe assigned backup master (smallest active peer callsign)
rosterstring[][master, …all known callsigns]

Sent by the master every BEACON_INTERVAL (8 s), always in BPSK. It is the heartbeat, the roster sync, and the implicit MASTER_CLAIM.

CHAT

{type, src, dst:"ALL"|callsign, text}. Broadcast vs. directed. Sent in BPSK (robustness over speed for short text).

BULK_META

{type, src, dst, transfer_id, filename, total_blocks, total_size} — starts a file/image transfer. transfer_id is 8 hex chars; total_blocks = ceil(total_size / 220).

BULK_BLOCK

FieldTypeMeaning
transfer_idstring
seqintblock index 0 … total_blocks−1
datastringbase64 of ≤ BLOCK_SIZE (220) raw bytes
crcuint32crc32(raw_block) — per-block integrity

Sent in the transfer’s current mode (QPSK, or BPSK after an adaptive downshift). A block whose crc fails on receipt is silently dropped; ARQ re-requests it.

BULK_END

{type, src, dst, transfer_id} — “that’s all the blocks I have for now.”

BULK_STATUS

{type, src:receiver, dst:sender, transfer_id, missing:int[]} — the receiver’s ACK/NAK. missing == [] ⇒ complete. Sent in BPSK from the end-of-transfer path; the drop/resume paths use the station’s default mode.

5  Session state machines

5.1  Roster

Every station keeps roster: {callsign → {last_seen, status}} locally, updated on every decoded frame from that callsign and from every BEACON’s roster list.

5.2  Roles

5.3  Master election & multi-level failover

The old design chained through one assigned backup only. It now uses a succession line that every station derives identically from its own roster:

succession_line = sorted( {self} ∪ {peers with status == ACTIVE}  \  {presumed-dead master} )
pos             = index of self in that line

claim mastership when:   time_since_last_beacon  >  BEACON_TIMEOUT + pos * BEACON_INTERVAL
Implementation invariant (the deadlock rule). Any frame that must be sent in response to a received frame (BULK_STATUS after BULK_END, the resume BULK_STATUS after a JOIN_REQUEST, …) is dispatched as a background task — never await-ed on the single receive loop’s call chain, because that loop is also what delivers the TX_GRANTED for that very send.

6  Chat

  • Broadcast: CHAT{dst:"ALL", text}. Every station with dst ∈ {"ALL", self} displays it.
  • Directed / private: CHAT{dst:"TA2XYZ", text}. Only TA2XYZ displays it; it still occupies the shared channel, it is just not addressed to anyone else.
  • Sent in BPSK. Contends via the same LBT + back-off as any frame — nothing is dropped, it waits its turn, including waiting for a control window if a bulk transfer is in progress (§7.3).

7  Bulk transfer (image / file) with ARQ

7.1  Receiver

  1. BULK_META → create the inbound transfer, received = {}.
  2. BULK_BLOCK → verify crc32(data) == crc; on match store received[seq], on mismatch drop it.
  3. BULK_END → missing = [s for s in 0…total_blocks−1 if s not in received]. Send BULK_STATUS{missing} (background task). If missing == [], write the file and mark complete.

7.2  Control window — keeping chat and beacons alive during a transfer

A back-to-back block stream would monopolise the half-duplex channel: chat, and even beacons, would starve, and stations would wrongly elect themselves master. So _send_blocks deliberately pauses to open the channel.

StatePause everyPause length
Quiet (baseline)CONTROL_WINDOW_EVERY = 3 blocksCONTROL_WINDOW_PAUSE = 1.2 s
Busy (contended)1 block1.5 s

7.3  Adaptive modulation

No pilot-based per-subcarrier bit loading yet (needs a channel estimator — §10). Instead the ARQ round is the link-quality signal:

if mode == QPSK and (missing_this_round / blocks_sent_last_round) > 0.15:
        mode ← BPSK        # for the rest of this transfer; downshift only

The receiver needs no notification — every frame’s header carries its own mode flag, so a transfer can switch mid-stream and still decode.

7.4  Drop / reconnect / resume

  • /drop closes the TCP socket but keeps all state in RAM.
  • /reconnect re-opens it, forces role LISTENER, sends JOIN_REQUEST, and re-requests missing blocks for every incomplete inbound transfer.
  • The other side reacts to that JOIN_REQUEST (or to the station going ACTIVE again) by re-sending the blocks it still holds — even with no active ARQ loop, as a background task.
  • Net effect: a station can vanish mid-transfer and, on return, the transfer finishes only the missing part — it never restarts.
